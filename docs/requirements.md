# 第一版需求与验收规则

确认日期：2026-10-25（Asia/Shanghai）。

## 依据与范围

来自用户引用的「大学生生活管理工具」对话中的生活费管理需求、最终修订和三张附图。引用中的助手完整计划未能读取，返回的是内容引用占位符，因此没有将其未读取内容当作已确认要求。

用户在本次开发中明确选择：先完成可安装的手机网页版；并要求把开发过程和内容提交到 `mik1e80/College-Student-Life-Management-Tool`。

当前只实现生活费管理。时间管理、原生 Android / iOS、账号和云同步列为后续工作，不显示没有实际功能的入口。

## 分类

| 项目 | 规则 |
| --- | --- |
| 初始大类 | 餐饮、生活用品、学习支出、社交娱乐、服饰数码、通勤交通、医疗健康、其他与备用金 |
| 初始小类 | 餐饮下早餐、午餐、晚餐，其他大类初始为空 |
| 排列 | 大类、小类均采用三列网格，从左到右排列；末格提供添加入口 |
| 新建 | 用户可自行添加大类和小类，同级不允许重名，名称 1～16 字 |
| 保留 | 不提供删除入口或删除操作，历史记录留在原分类 |
| 生效 | 分类从创建当天开始使用，不允许为尚不存在的分类补记历史 |

## 预算与实际

| 项目 | 规则 |
| --- | --- |
| 月计划 | 各小类填写每日预计金额，自动计算当月合计；不同月份独立制定 |
| 当前月生效 | 从保存当天生效，修改不回写到昨天及更早日期 |
| 未来月生效 | 从该月 1 日起生效 |
| 历史预算 | 只读；使用生效日期版本保留历史金额 |
| 今日实际 | 可填写和调整；必须显式保存 |
| 跨日 | 零点后，新日期的实际金额为空，旧日期已有记录锁定 |
| 漏记补录 | 仅对未填的历史实际金额开放一次补录；二次确认后立即锁定 |
| 0 元 | 有效金额，属于已记录；历史补录 0 元同样消耗唯一机会 |
| 未记录 | 独立显示，不自动补成 0 元 |
| 差值 | 预计减实际；绿色正数带 +、红色负数、零值默认颜色；缺少任一值时不计算 |
| 精度 | 整数分存储，输入最多两位小数，范围 0～999999.99 元 |

小类详情的上部展示上下排列的预计、实际与差值，下部为日期日历；两部分高度大致相等。未来日期仅预览预算，不开放填写实际金额。

## 日展示与月展示

支持日统计、月统计、分类实际支出、逐日支出趋势以及 CSV 导出。预计总额可以包括已安排的未来预算；实际总额仅包含已填实际金额；结余只比较预算和实际都已填写的项目。未记录数量单独提示。

## 产品决策

- 第一次在月中使用，从今天开始预算，避免人为制造过去的计划。
- 不自动沿用上月预算，避免把未确认的计划当作已设置。
- 未设预算也允许记录真实支出；该支出计入实际总额，不参与预算差值。
- 允许导出完整 JSON 和 CSV；第一版不提供导入和清空功能。
- 第一版按设备本地日期判断跨日，并明确本地锁定的限制。
