# 数据结构与实现

## 1.2.0 周期数据

状态 `schema` 升级到 2，存储键仍为 `yiri-campus-life-v1`。读取 schema 1 时只补上新字段、保持旧的 `plans` 与 `records` 原样，因此旧金额、日期、补录标记与锁定不变。

- `cadences[itemId]`：按生效日期排序的 `{from, unit}`，unit 为 day / month / year。未设置视为 day。
- 原 `plans` 和 `records`：继续保存每日预算与每日实际，键不变。
- `periodPlans`：月、年预算，键为 `unit:periodStart:itemId`，保留金额版本。
- `periodRecords`：月、年实际，同样按周期键保存一条，包含金额、首次/最近保存时间及补录标记。

周期按自然天、月、年判断结束；当前周期可修改，结束后已有记录锁定、空缺可补录一次。更换周期只从生效日期起改变含义，旧日期仍用原周期；若当前周期已有实际，禁止把它改成另一周期。年预算同年共用，月预算每月独立。

统计先按周期聚合，待记录数量按周期计算。再对所选日期范围分配预算与实际，使用 `floor(total*(i+1)/n)-floor(total*i/n)` 精确分配整数分；n 为该周期中项目及计费方式均已生效的天数。完整周期的份额之和严格等于输入金额，包括闰年、月中开始和零元。原日预算 n=1，因此历史每日结果保持一致。CSV 每周期输出一次，并分别给出整期金额与当前统计范围的折算金额。

以下为初版实现说明，日记录结构继续沿用；月/年结构以上述说明为准。

## 状态

`schema` 标记数据结构版本，`revision` 标记保存版本。`createdOn`、分类和小类的创建日期均为设备本地 `YYYY-MM-DD`。

`categories` 保存大类；`items` 通过 `categoryId` 关联大类。分类由应用生成稳定 ID；1.3.0 改名只变更 `name`，历史和导出使用当前名称，金额、日期与关联键不变。删除只允许全历史无实际记录的分类（含 0 元、补录和旧周期均需检查）；删除小类清理日预算、月/年预算与周期变更，删除大类先检查全部子项再整体清理，避免部分删除。保存时沿用跨窗口锁和最新账本读取。

`plans` 的键为 `YYYY-MM:itemId`，值为按 `from` 排序的 `{ from, cents }` 列表。读取某日时选取该日之前最近的有效版本。修改计划只能以今天或未来月份第一天为生效日期，不需要实际生成每一天的记录，就可保持历史预算不变。

`records` 的键为 `YYYY-MM-DD:itemId`，值含 `cents`、首次保存和最后保存时间以及 `backfilled` 标记。键不存在表示未记录；0 分表示已明确记录 0 元。历史日期已有键即禁止再写入；历史空缺允许创建一次。

## 保存与日期边界

每次保存前从 localStorage 重新读取并校验，再克隆修改；校验失败或存储写入失败时不替换内存状态。支持 Web Locks 的浏览器在锁内完成重新读取和同步写入，协调多个打开窗口；其他浏览器使用单次同步读改写。

前台每 15 秒检查日期，页面恢复可见或获得焦点时再次检查。跨日不是依赖计时器解锁或锁定：保存实际金额时始终重新传入最新日期，由核心规则决定能否写入，因此应用关闭过夜也不会使旧记录继续可编辑。

实际金额和预算提交均校验整数分。输入金额用字符串拆分为分，避免浮点小数累加。预算批量保存先验证所有条目，再进行任何写入。

## 统计口径

- `planned`：所选期间所有已设置预算的合计。
- `actual`：所选期间所有已记录实际金额的合计。
- `pairedPlan / pairedActual / pairedCells`：预算和实际均存在的项目对应金额和数量。
- `difference`：配对项目预计合计减实际合计。
- `recorded / expected`：已记项目数和分类生效后应记项目数。

分类建立前不生成应记项目。未来日不计入“截至今天待记录”的数量。

## 离线与数据边界

静态应用资源预缓存，正常联网请求优先；网络失败后从缓存读取。只处理同源 GET 请求。Service Worker 更新时仅清理本应用旧版本资源缓存，不清理其他应用缓存，也不清理用户 localStorage。

JSON 备份由用户触发下载，无账号接口、无埋点、无第三方请求。CSV 导出给用户可控分类名称加上公式前缀防护，保留正常数字与缺失状态。

本地存储受当前浏览器与域名隔离，不跨设备同步。浏览器清理、独立 PWA 存储行为、设备时间变更均有边界；此版本不声称服务端不可篡改。后续如需要严格校时、云同步和备份恢复，应引入服务端身份、不可变流水和迁移策略。
